# עולם הדמו — זריעה, צופה ומחיקה

שלב 3 בתכנון `agent-briefs/demo-users-design.md`. שלושה סקריפטים שמריצים מהמחשב (Admin SDK). אין שום כפתור בדפדפן שמפעיל אותם.

## מה נוצר

| מה | פירוט |
|---|---|
| ערים | `דמו · תל אביב` (`demo-tlv`), `דמו · באר שבע` (`demo-b7`), `דמו · חיפה` (`demo-haifa`) ושכונות דמו. כולן `isDemo: true` |
| יחידות | `יחידת דמו א׳` (`demo-unit-a`), `יחידת דמו ב׳` (`demo-unit-b`), `גדוד מילואים דמו` (`demo-reserve`), עם פלוגות |
| אנשים | 33 פרסונות בדויות (`demo_tlv01`…), כל אחת לפי תרחיש לו״ז S01–S33 או תוכנית הליכה, ולפי מסע הרשמה (J1–J4, הליכה). לכל אחת `core.isMockData`, `core.demo`, `core.discoverable: false`, ו-`tenantId`/`authorityId` של דמו |
| לו״ז | נבנה במנוע האמיתי: מנוע הלו״ז v2 (`buildWeek`) או תוכנית ההליכה (`recommendWalkPlan`). נכתב ל-`userSchedule` כמו אצל משתמש אמיתי, 60 יום אחורה ו-14 קדימה |
| היסטוריה | 60 יום: אימוני כוח, ריצות והליכות, צעדים (`dailyActivity`), סטריק, פוסטים בפיד, צ׳ק-אינים בפארקים |
| ליגות | הניקוד נכנס רק לסקופים של הדמו (עיר, שכונה, קבוצה של דמו), עם אותן פונקציות שהשרת משתמש בהן |
| חברתי | 10 קבוצות פרטיות (`isPublic: false`), צ׳אט לכל קבוצה, כמה הודעות פרטיות, עוקבים |

**פארקים:** הצ׳ק-אינים מפנים לפארקים האמיתיים של תל אביב, באר שבע וחיפה, **בקריאה בלבד**. הצ׳ק-אין עצמו נשמר תחת רשות הדמו, ולכן רק דשבורד הדמו רואה אותו. לפארק האמיתי ולרשות האמיתית לא נכתב כלום.

**מה לא נוצר:** פרופיל ציבורי, נוכחות על המפה, מיקומים, אירועים, דיווחי תקלות, ביקורות, חשבונות כניסה (Auth). משתמשי הדמו קיימים רק כמסמכים.

## לפני שמתחילים

1. השלבים הקודמים צריכים להיות פרוסים: השומרים (#549) והדשבורדים (#550), כולל חוקי Firestore ו-functions.
2. מריצים מתיקיית הפרויקט שבה יש `.env.local` עם `FIREBASE_SERVICE_ACCOUNT_KEY`.
3. אסור ש-`FIRESTORE_EMULATOR_HOST` יהיה מוגדר בטרמינל (הסקריפט יעצור).

## הפקודות (בסדר הזה)

**1. הרצה יבשה. רק סופרת, לא כותבת כלום:**
```bash
npx tsx scripts/demo/seed.ts --project appout-1 --dry-run
```

**2. זריעה (כ-6,000 מסמכים, בערך 2–4 דקות):**
```bash
npx tsx scripts/demo/seed.ts --project appout-1 --confirm "צור את עולם הדמו"
```
אפשר להריץ שוב. אותם מזהים נכתבים מחדש, ולכן לא נוצרים כפילויות והליגות לא נספרות פעמיים.

**3. הוספת החשבון שלך כצופה:**
```bash
npx tsx scripts/demo/add-viewer.ts cali.appout@gmail.com --project appout-1
```
- האימייל מתורגם ל-uid דרך Firebase Auth בזמן הריצה.
- החשבון נוסף ל-`demo_registry/viewers` ולמנהלי ערי הדמו ויחידות הדמו.
- עם `--groups` החשבון גם מצטרף לקבוצות הדמו ולצ׳אטים שלהן. זו הכתיבה היחידה למסמכים של החשבון שלך, והמחיקה מחזירה אותה.

**4. מחיקה. קודם הרצה יבשה שמציגה כל מסמך שיימחק:**
```bash
npx tsx scripts/demo/purge.ts --project appout-1
npx tsx scripts/demo/purge.ts --project appout-1 --summary      # רק ספירות
```
מחיקה אמיתית:
```bash
npx tsx scripts/demo/purge.ts --project appout-1 --confirm "מחק את עולם הדמו"
```

## הגנות

- **בלי `--project` מפורש:** שום סקריפט לא רץ.
- **בלי ביטוי האישור המדויק:** אין זריעה ואין מחיקה.
- **כל מסמך נבדק לפני הכתיבה הראשונה:**
  - מותר לכתוב רק לנתיבים של דמו: `demo_…`, `demo-…` ו-`demo_registry`.
  - שדות משתמש, רשות וקבוצה חייבים להיות של דמו או של צופה רשום.
  - כל בדיקה שנכשלת עוצרת הכול. לא נכתב אף מסמך.
- **אם במזהה של דמו כבר קיים מסמך שלא מסומן כדמו:** הזריעה נעצרת.
- **המחיקה מוחקת רק מה שיש עליו שני סימונים:**
  - משתמש: uid שמתחיל ב-`demo_` **וגם** `core.demo`.
  - רשות, יחידה או קבוצה: מזהה שמתחיל ב-`demo-` **וגם** `isDemo: true`.
  - אם יש פער בין הרישום (`demo_registry`) לבין המשתמשים בפועל, או שיש צ׳אט עם משתמש אמיתי שאינו צופה, המחיקה נעצרת ולא נמחק כלום.
- **מסמכים של הצופה לא נמחקים.** רק מזהי הדמו מוסרים מהם.
- **רשימת המחיקה לכל משתמש** משקפת את `purgeUserData` (מחיקת חשבון). בדיקה אוטומטית נכשלת אם `purgeUserData` יתחיל לגעת בקולקשן שהמחיקה כאן לא מכסה.

## בדיקה על האמולטור (בלי פרודקשן)

```bash
bash scripts/ci/run-emulator-suites.sh --only 8089 scripts/demo/__tests__/demo-world.emulator.test.ts
```
הבדיקה עוברת את כל הסבב:
1. זריעה (פעמיים).
2. בדיקה ששאילתות של משתמשים אמיתיים לא מחזירות שום דבר מהדמו.
3. הוספת צופה.
4. מחיקה.
5. בדיקה שלא נשאר אף מסמך דמו ושהמסמכים האמיתיים לא השתנו.

ידנית מול אמולטור שרץ:
```bash
npx tsx scripts/demo/seed.ts --project demo-local --emulator --days 7 --confirm "צור את עולם הדמו"
```

## הערות

- **לוחות אישיים של עיר:** הפוסטים והצעדים של הדמו נשמרים עם `ageGroup: 'demo'`, ולכן אף לוח אמיתי לא מחזיר אותם. לוח הקבוצות וסטטיסטיקות הליגה של העיר והשכונה עובדים כבר עכשיו. כדי שהצופה יראה את הדמו גם בלוחות האישיים של עיר, צריך את שלב 5 (גיל `demo` לחשבון הצופה).
- **הלידרבורד הישן (`onWorkoutCreate`)** מזכה לפי החודש שבו הזריעה רצה, לא לפי תאריך האימון. זה קורה רק בתוך דייר הדמו.
- **הסימולטור החי (שלב 4):** הפונקציה `demoSimulatorTick` (`functions/src/demo-life/`). היא קוראת את הפרסונות מ-`demo_registry/personas` (בלוק `life` לכל פרסונה: הלו״ז שהמנוע בנה, התמדה, טון). **אחרי שמיזגו אותה, מריצים את הזריעה פעם אחת שוב** כדי שהבלוק ייכתב. בלי הבלוק הסימולטור לא עושה כלום.
- הזריעה והסימולטור משתמשים באותם בוני מסמכים (`functions/src/demo-life/session-docs.ts`, `daily-docs.ts`) ובאותה רשימת היתר (`functions/src/demo-life/guard.ts`, ש-`lib/guard.ts` מייצא).
- **מה לא נבנה עדיין:** בדיקת הזליגה היומית (שלב 6).
