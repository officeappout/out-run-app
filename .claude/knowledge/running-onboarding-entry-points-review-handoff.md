## What this branch does

Fixes the entry points into the running-onboarding questionnaire for **existing** users (new-user entry via Gateway already worked before this branch — see "Pre-existing state" below). Four problems, found and scoped in this order:

1. A client-supplied `isNewUser` flag let a returning user's Firestore write reset their city affiliation and access level.
2. The re-entry guard on `/onboarding-new/dynamic` blocked every already-onboarded user regardless of track.
3. Two home-screen CTAs sent a known-identity user through the identity form again.
4. Three other CTAs never seeded the track signal the (already-fixed) storage layer reads, so they silently defaulted to the strength tree.

Before this branch, two prior fixes already landed on `main` on 21.08.2026 (**a day before** the gap-map audit this work was originally briefed from — that audit is partially stale, see commit `9f19be56` and `488cd1512`):

- `profile-completion.service.ts`'s `runningPlan`/`runningPace` items already have a working `jitPath` mechanism, consumed correctly by `ProfileProgressBar` (the **live** completion widget — `ProfileCompletionWidget.tsx` is a dead duplicate, zero mounts anywhere in the repo, flagged but not deleted).

So: a brand-new user picking "ריצה" at Gateway already reaches the running question tree. This branch is entirely about **returning** users.

### 5. `1a28b090` — fix a bug David found in commit 3's birthDate handling
