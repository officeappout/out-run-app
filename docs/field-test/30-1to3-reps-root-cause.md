## המקור האמיתי: `TIER_TABLE` — מנגנון גנרי, לא ספציפי-hybrid, לא קשור לשם-התרגיל

`workout-generator.types.ts:51-53`:
```ts
export const TIER_TABLE: Record<TierName, TierConfig> = {
  elite: { reps: { min: 1, max: 3 }, ... },  // levelDelta ≥ +2
  hard:  { reps: { min: 1, max: 3 }, ... },  // levelDelta = +1
  ...
  easy:  { reps: { min: 10, max: 15 }, ... }, // levelDelta -1/-2
};
```
`resolveTier(levelDelta)` (שורה 65-69): `delta≥2→elite`, `delta===1→hard` — **שניהם נותנים 1-3 חזרות, לכל תרגיל, בלי תלות בסוג-התרגיל**. זו טבלה **אחידה** שמניחה "רמה קשה = פחות חזרות" — הגיוני לתרגיל-מיומנות/עומס (משיכת-יד-אחת, סקוואט-פיסטול), **לא הגיוני** לתרגיל בטן/רגליים בסיסי בלי משקל.

**`assignVolume` (`workout-budgeting.utils.ts:544+`), הפונקציה המרכזית שמייצרת נפח לכל תרגיל בכל אימון (לא רק hybrid)**, קוראת ל-`resolveTier(delta)` על סמך `scored.levelDiff` — פער-הרמה של **המשתמש הספציפי** מול רמת-התרגיל, **בתחום (domain) הספציפי** (כאן: core/isolation). מסקנה: זה קרה כי החשבון שבדקת בו (super-admin) קיבל `levelDelta≥1` עבור "כפיפות בטן"/"עליות תאומים" בתחום הזה — כלומר רמת-הbטן/isolation שלו בפרופיל נמוכה/לא-מוערכת ביחס לרמת-התרגילים שנבחרו.
