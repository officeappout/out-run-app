כל הבדיקה למטה מקורה בקובץ אחד: `src/features/admin/components/routes/RouteEditor.tsx` (752 שורות, זה ה"מחולל שבילים ידני" — `src/app/admin/routes/new/page.tsx` רק עוטף אותו). "נקודות ביניים" שתיארת זה כנראה אותו מנגנון-קליק-נקודה-נקודה בתוך הכלי הזה עצמו — לא מצאתי כלי נפרד.

## 1. Directions API תמיד — אין מצב "ללא הצמדה" נסתר, אפילו לא דגל

כל קליק על המפה (`handleMapClick`, שורה 236-260) קורא ל-`fetchSnappedRoute` (שורה 90-107) — שקוראת **תמיד** ל-Mapbox Directions API (`.../directions/v5/mapbox/${profile}/...`, profile = `walking` או `cycling` לפי סוג הפעילות). **אין שום `snap=false`, דגל מוסתר, או מצב-ציור-חופשי בקוד — חיפשתי בכל הקובץ.**

**הדרך היחידה שמייצרת קו ישר היא נפילה על שגיאה** (שורה 249-253 ו-283-284) — אם קריאת ה-API נכשלת (רשת/שגיאת שרת), הקוד נופל לקו ישר בין שתי הנקודות **בשקט**, בלי שום דרך למשתמש להפעיל את זה בכוונה. זה לא "מצב", זו טיפול-שגיאה בלבד — לכן גם אם הצד הצפוני "יצא ישר" פעם, זה לא שחזיר-מבוקש.

## 2. הערכה: מצב "ציור חופשי" (קו ישר במקום Directions)

**קטן — קובץ אחד, ~20-30 שורות, לא נוגע במשהו שמשתמשים רואים.**

- `RouteEditor.tsx` הוא כלי-פאנל בלבד (super-admin/authority-admin), לא מגיע לאף מסך צרכן.
- משתני מצב חדש: `snapToRoads` (boolean, ברירת מחדל true).
- ב-`handleMapClick`: כשה-toggle כבוי, לדלג על `fetchSnappedRoute` ולדחוף ישירות `{geometry:[from,to], distanceKm:haversineKm(...)}` — **בדיוק אותו literal שכבר קיים כ-fallback-שגיאה היום** (שורה 250-253), רק הופך לנתיב מכוון במקום נפילה שקטה.
- אותו שינוי בלולאת ה"נתב-מחדש כשמשתנה סוג-פעילות" (שורה 270-291).
- toggle UI קטן ליד בורר-הפעילות הקיים (אותו דפוס עיצוב כבר קיים בקובץ לכל שאר הבוררים).
- **הפורמט הנשמר לא משתנה** — `path`/`fullPath` נשאר מערך של `[lng,lat]` בדיוק כמו היום, בלי קשר למקור הנקודות.

## 3. תצוגת לוויין — לא קיימת בשום מקום באפליקציה, לא רק פה

חיפשתי בכל `src/` — **אפס** אזכור אמיתי של סגנון-לוויין (שני האזכורים היחידים ל"satellite" בכל הריפו הם ל-GPS satellite-signal ולהערת-קוד כללית, לא סגנון מפה בפועל). `RouteEditor.tsx` קבוע על `mapbox://styles/mapbox/streets-v12` בלבד (שורה 688).

**הערכה: קטן — קובץ אחד, ~15-25 שורות.**
- `mapStyle` state (`'streets' | 'satellite'`) → `mapbox://styles/mapbox/satellite-streets-v12` כשמופעל.
- toggle UI פשוט (2 כפתורים).
- **בדקתי סיכון ספציפי**: `applyHebrewLabels` (שורה 50-62) שכותב מחדש שמות-עברית על שכבות-טקסט **כבר מחובר ל-event `style.load`** (שורה 691) — מחליפים סגנון מפעיל את זה מחדש אוטומטית, בלי צורך בקוד נוסף. סיכון נמוך.

## 4. GPX Import — לא קיים בכלל, בשום מקום

חיפוש מלא (`gpx`, `trackpoint`, סיומת `.gpx`) בכל `src/` וב-`package.json` — **אפס תוצאות**. אין ספרייה מותקנת, אין parser, אין שדה בשום טופס.

**הערכה: בינוני — כ-2 קבצים, ~100-150 שורות.**
- קובץ parser קטן חדש (`gpx-parser.ts`, ~40-60 שורות) — GPX הוא XML פשוט (`<trkpt lat="..." lon="...">`), אפשר לפרסר עם `DOMParser` הדפדפני בלי תלות חיצונית חדשה (לא בדקתי אם יש כבר ספריית XML בריפו, אבל GPX פשוט מספיק שזה לא נדרש).
- שינוי ב-`RouteEditor.tsx` (~30-50 שורות) — כפתור "ייבוא GPX" + input-קובץ, ו**נתיב-קוד נפרד** מקליקים רגילים: מסלול מיובא מ-GPX אמור לבנות את `fullPath` **ישירות מנקודות ה-GPX, בלי לעבור דרך Directions API בכלל** (זה כל הנקודה — ה-GPS כבר "צילם" את השביל האמיתי, לא צריך לנתב-מחדש).
- **פורמט האחסון: זהה** — אותו מערך `[lng,lat]` שנכתב ל-`official_routes.path` כבר היום. אין צורך בשינוי סכמה.

## 5. המלצה: הכי מהיר ובטוח לפני ההשקה
