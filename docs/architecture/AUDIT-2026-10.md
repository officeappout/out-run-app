## 1. מפת חי / מת

### 1.1 שיטה, ומה היא לא רואה

- **גרף import סטטי, symbol-aware.** כל `import`/`export … from`/`import()`/`require()` ב-`src/`, `scripts/`, `tests/` נפתר עם ה-resolver של TypeScript (כולל `@/*`). import בשם דרך barrel (`export * from` / `export { X } from`) מוביל **לקובץ שמצהיר על X**, לא לכל הקבצים שה-barrel מייצא. בלי זה (גרסה ראשונה של הגרף) `BottomNavbar` → `@/features/user` → `OnboardingWizard` גרם לכך ש-`OnboardingWizard` "נראה" חי מכל 120 הדפים, וכל קובץ שיש לו barrel נראה חי.
- **נקודות כניסה:** כל `page/layout/template/loading/error/not-found/route` תחת `src/app`, וגם `src/middleware.ts`, `src/instrumentation*.ts`. משתמש = כל מה שלא תחת `src/app/admin`, `src/app/authority-portal`, `src/app/api`.
- **אומת ידנית:** לכל קובץ "מת" חיפשתי את שמו בטקסט בכל `src/`, `functions/src`, `capacitor.config.ts`, `next.config.mjs`. כל הפגיעות היו הערות, או תאום בעל אותו שם בנתיב אחר (לדוגמה `GymEquipmentEditorForm` החי נמצא ב-`features/content/equipment/gym/admin/`, המת ב-`features/admin/components/`). לא נמצאו `import()` עם template string או `new URL()` לקבצי קוד.
- **מוגבלות 1 — דגלים בזמן ריצה:** הגרף לא יודע ערכי דגלים. ענף `flag ? A : B` נספר כחי בשני הצדדים. הערכים בפרודקשן (`system_config/feature_flags`) **לא נקראו** (אין גישה לפרודקשן). §1.4 מפרט את הדגלים ואת ברירות המחדל שלהם מ-`src/hooks/feature-flag-defs.ts`.
- **מוגבלות 2 — ענפי זמן ריצה שאינם דגל:** קובץ שנגיש רק דרך ענף שבפועל לא קורה (למשל fallback של `switch`) נספר חי. מקרה ידוע אחד ב-§1.4.
- **מוגבלות 3 — import של type בלבד** נספר כקשת. קובץ שנגיש רק דרך `import type` נספר חי (אין בכך נזק לרשימת המתים; היא שמרנית).
- הסקריפטים שהפיקו את המספרים לא נכנסו ל-PR הזה (מסמך בלבד). מומלץ להכניס אותם ב-PR של השומר (§3.8), כדי שהרשימה תתחדש לפני כל גל.

## 3. הצעת תקנים

קצר ומבוסס על מה שה-repo כבר עושה טוב (`progression-hub`, `search`, `ui/v2`, `__tests__`, `server-only`).

### 3.1 מבנה תיקייה לכל feature

```
src/features/<domain>/
  screens/      # קומפוזיציה ברמת מסך; ה-page ב-src/app רק מרנדר אחד מאלה
  components/   # קומפוננטה אחת לקובץ, רק רינדור
  hooks/        # state + data wiring (useX.ts)
  services/     # גישה ל-Firestore/API (x.service.ts); בלי React
  lib/          # לוגיקה טהורה (x.ts / x.utils.ts) — בלי React ובלי Firebase
  store/        # Zustand (axioms §7)
  types/        # x.types.ts
  data/         # טבלאות/קטלוגים (x.data.ts) — פטור מתקציב השורות
  server/       # קוד שרץ רק בשרת (import 'server-only'), נקרא מ-src/app/api
  admin/        # עורכי פאנל של הדומיין — לעולם לא מיובא ממסך משתמש
  legacy/       # קוד שמחכה להסרת דגל (כמו search/legacy היום), עם שם הדגל בכותרת
  __tests__/
```

`src/app/**/page.tsx` דק: params, בחירת דגל, `<Screen />`. יעד ≤ 150 שורות.
שורשים כפולים (`src/@core`, `src/core`, `src/utils`, `src/constants`) מתאחדים ל-`src/lib` (רובם מתים או קטנים ממילא).

### 3.2 תקציב גודל

| סוג | יעד | חסם לקובץ **חדש** |
|---|---:|---:|
| קומפוננטה / hook | ≤ 300 | 500 |
| service / lib | ≤ 400 | 600 |
| `page.tsx` / `route.ts` | ≤ 150 | 300 |
| `*.data.ts`, `src/lib/data/**`, `*.fixtures.ts`, טסטים | פטור | פטור |

קובץ קיים מעל התקציב: מותר לגעת בו, אסור לו לגדול (ratchet, §3.8). כשנוגעים בו בשביל פיצ'ר, מוציאים קודם את החלק שנוגעים בו.

### 3.3 קומפוננטה אחת לקובץ

תת-קומפוננטות פרטיות קטנות (≤ 40 שורות) מותרות באותו קובץ. כל מה שגדול מזה או שמיוצא — קובץ משלו. זה בדיוק מה שחסר ב-`FreeRunDrawer`, `SmartWeeklySchedule`, `RouteCarousel`, `admin/questionnaire`.

### 3.4 UI משותף

- כל UI חדש עובר דרך `src/components/ui/v2` (55 primitives היום: `Sheet`, `Card`, `Chip`, `Button`, `IconButton`, `SectionHeader`, `StoryBars`…). `scripts/ci/v2-raw-style-grep.sh` כבר מודד סטייה — להשאיר.

### 3.5 גבולות

- **admin → משתמש: אסור.** קוד ב-`src/features/admin/**` או `src/features/*/admin/**` לא מיובא מקוד שנגיש ממסך משתמש. קריאה משותפת (למשל `authority.service` ל-`CommunityCoLogo`) עוברת ל-`src/lib/<x>` או ל-`services/` של הדומיין. אכיפה: ESLint `no-restricted-imports` (advisory בהתחלה; 8 נקודות כניסה ידועות ב-§1.6).
- **אין `require()` בקוד לקוח** ואין import של barrel שלם (`import * as`) — זה מה שמשך את עורך התרגילים לדף הבית.
- **barrels:** לא יוצרים barrels חדשים ברמת דומיין עם `export *`. מייבאים בנתיב ישיר. barrel קיים מותר, אבל רק ל-API ציבורי מצומצם.
- **שרת/לקוח:** `'use client'` ברמת screen. מודול שמשתמש ב-Admin SDK מתחיל ב-`import 'server-only'` (כבר 150 קבצים כך). `src/app/api/**/route.ts` דק: auth guard (axioms §15) + קריאה ל-`features/<domain>/server/*`.
- cross-domain: היום יש 1,860 קשתות import בין דומיינים (`workout-engine→parks` 157, `home→user` 114…). לא מתקנים בכוח; כשמפצלים קובץ, מה שמשותף עובר ל-`src/lib`.

### 3.6 שמות

`PascalCase.tsx` לקומפוננטה · `useX.ts` ל-hook · `x.service.ts` · `x.utils.ts` / `x.ts` ל-lib טהור · `x.types.ts` · `x.data.ts` · `x.config.ts`. סיומת `V2` רק בתקופת דגל; אחרי הסרת הדגל, מוחקים את v1 ולא משנים שם (שינוי שם = diff רועש בלי ערך).

## 4. סדר עבודה מול גלי ה-i18n ותיקוני העיצוב

עקרונות:
1. **PR אחד = סוג שינוי אחד.** מחיקה, פיצול, חילוץ מחרוזות ותיקון עיצוב לעולם לא באותו PR. פיצול הוא "העברה בלבד, התנהגות זהה" — diff של הזזה, בלי שינוי מחרוזת או מחלקה.
2. **מחיקה לפני הכול.** אף אחד לא מתרגם או מתקן עיצוב בקובץ מת.
3. **פיצול רק לפני שגל נוגע באזור, ורק כשהתיקייה לא נעולה ע"י גל 0** (טבלת הנעילות `docs/i18n/LOCKS.md` מקבלת גם נעילות "split").
4. **כשיש דגל v2 שעומד להידלק — קודם להדליק ולמחוק v1, אחר כך לחלץ.** חוסך תרגום של טקסט שעומד להימחק.
