## חלק 3 — השוואת מאקרו (בלוקים)

### 3.1 גזירת "בלוק" מהמחולל החדש — איך נגזר, במפורש

אין בלוקים מפורשים בפלט המחולל — הבלוק נגזר מ-`exerciseRole` + `pairedWith` +
`supersetType` + `protocolBlock` + `pyramidSequence` + `appliedProtocol` (ברמת
האימון), כך (`scripts/audit/analyze-benchmark.ts`, `deriveNewBlocks`):

1. כל תרגילי `exerciseRole==='warmup'` באימון אחד → **בלוק חימום אחד** (תואם ל"סט
   חימום" הישן — קבוצת 1-6 תרגילים לסבב יחיד).
2. כל תרגילי `exerciseRole==='cooldown'` → **בלוק סיום אחד** (1-3 תרגילים).
3. תרגילים עם `protocolBlock==='tabata'` → בלוק טבאטה (יכולת חדשה).
4. תרגילים עם `pyramidSequence` → בלוק פירמידה (יכולת חדשה).
5. `appliedProtocol==='emom'` ברמת האימון → כל חלק ה-main שנותר מסווג כבלוק EMOM אחד
   (אין סמן פר-תרגיל ל-EMOM, בניגוד לטבאטה/פירמידה).
6. זוגות עם `pairedWith` משותף: אם `supersetType==='staggered'` (או
   `appliedProtocol==='antagonist_pair'`) → **זוג אנטגוניסטי (יכולת חדשה)** — מכוון,
   ראו הערת §2. אחרת (`'compound'`, אותה קבוצת-שריר) → **יעד כפול/סופר סט**, נשווה
   לצורה הישנה.
7. תרגיל main עצמאי (לא זווג, לא פרוטוקול): אם `domain==='core'` → בלוק **ליבה**
   (1×סבבים בפועל), אחרת → בלוק **יעד** (1×סבבים בפועל).

| **ב — יכולת חדשה מוצהרת** | פירמידה 1,206 + זוג אנטגוניסטי 388 + טבאטה 154 | 1,748 | 9.5% |

**קטגוריית ג צנחה מ-2.3% ל-1.0%** — ישירות בזכות תיקון בלוקי הליבה (§3.3), שהיה
האחראי לרוב ה"חשוד" הקודם.

### 3.3 תיקון בלוקי ליבה (בוצע) + קטגוריה ג שנותרה

**נמצא ותוקן, בסבב הזה:** בלוקי "ליבה" לא היו נעולים ל-2 סבבים כמו אצל דוד — 53.3%
מהם קיבלו 3-5 סבבים. אותר: `BudgetDistributor.distribute()` (הנתיב הראשי, בחירת
דומיין-מכסה) מעולם לא נעל ליבה לערך קבוע — היא ירשה את טבלת הנפח הגנרית לפי קושי
(D1=3, D2=3-4, D3=4-5 סבבים, `DIFFICULTY_VOLUME` ב-`workout-budgeting.utils.ts`)
כמו כל תרגיל push/pull/legs, ואז נחתכה/התנפחה על ידי אותם caps/rebalance עיוורי-דומיין.

**התיקון (`BudgetDistributor.ts`):** נעילה חדשה, `CORE_FIXED_SETS=2`, בשתי נקודות —
מיד אחרי `assignVolume` (Step 1c, תיעוד+לוג) ושוב ממש לפני `totalSets` הסופי
(Step 5j, כדי לבטל כל שינוי שה-caps/rebalance/cluster-cap עשו ביניים). תרגילי פירמידה
פטורים (אותה בדיקה כמו ה-pin של הפירמידה עצמה). טסט: `core-set-lock.test.ts`, 7
מקרים, כולל חסינות מפני rebalance עם תקציב עודף.

**נמצא ותוקן, שני — מקור נפרד לגמרי:** `trio-modifiers.service.ts`'s
`applyEssentialGearFilter` (ה"naked" backfill — כשמעטים מדי תרגילים חסרי-ציוד נשארים
בבולט 1/Flow-Regression, ממלא מהמאגר הגולמי) חתם `sets:3` קשיח על **כל** תרגיל
שהיא מגייסת, ללא תלות בדומיין — לגמרי מחוץ ל-`BudgetDistributor`, ולכן מחוץ לתיקון
הראשון. אותר ישירות ע"י מעקב אחרי מופע אמיתי של "אופניים sets=3" (bolt=1,
location=home) עד השורה הזאת. **תוקן:** תרגיל-מועמד מדומיין core מקבל `sets:2`
במקום 3 (וגם בנתיב-המשנה שמחליף תרגיל "violation" שחומק מהסינון). טסט:
`trio-modifiers-core-set-lock.test.ts`, 3 מקרים.

## חלק 5 — נפח: סטים עובדים לקבוצת שריר (המדד שבאמת קובע)

**למה זה נמדד:** מספר התרגילים (חלק 3) קל לספור אבל לא בהכרח המדד הנכון —
Kassiano 2024 מראה שמגוון תרגילים ≈ אותם תרגילים כשנפח מושווה; Remmert 2025 מראה
שהתשואה משתטחת סביב 11 סטים לקבוצת שריר **בשבוע**. השאלה האמיתית: לאותו משך אימון
ורמה, כמה **סטים** נותן המחולל מול דוד — לא כמה תרגילים.

**איך נבנה:** `scripts/audit/build-session-volume.ts` — קורא רק מ-`snapshot.sqlite`
(אין Firestore, אין כתיבות נוספות), מוסיף שתי טבלאות:
`session_volume(run_id, domain, exercises_count, working_sets, total_reps,
est_time_under_tension)` (חדש) ו-`legacy_session_volume(workout_id, domain, ...)`
(ישן, אותו סכימה). `working_sets` (ישן) = "repeats של הבלוק × מספר תרגילים בו"
בדיוק כפי שהוגדר במשימה — במעשה: סכום `repeats` על פני כל שורת `set_exercises`
(לא-`exerciseid=0`) בבלוק, שקול מתמטית לנוסחה המבוקשת.

**סייג היקף חובה:** `legacy_session_volume` מוגבל ל-**189 התרגילים המגושרים
בלבד** — לתרגיל ישן אין `movementGroup` בכלל, כך שהדומיין שלו ידוע רק דרך מה שהוא
ממופה אליו בקטלוג החדש (`exercise_bridge`). תרגיל ישן לא-מגושר לא נספר, לא מיוחס
ל-domain=null בטעות — פשוט מדולג. זו הסיבה ש-n בטבלאות למטה קטן בהרבה מ-480
האימונים המלאים. `total_reps`/`est_time_under_tension` מבוססים על הנחת 3 שניות/חזרה
כשאין ערך אמיתי (בדיוק ברירת המחדל של `normalizeExercise`) — **בישן במיוחד** אין
דגל is_time_based, כך שתרגיל החזקה אמיתי (למשל פלאנק, min/max בשניות לא בחזרות)
מקבל את אותה הכפלה בטעות — מטה כלפי מעלה את `est_time_under_tension` הישן בדומיינים
עם הרבה החזקות (בעיקר core). **`working_sets` נקי מהבעיה הזאת לגמרי — הוא לא תלוי
בפרשנות reps/seconds.** לכן `working_sets` הוא המדד הראשי כאן, לא `est_time_under_tension`.

## 10 שאילתות SQL מוכנות (`scripts/audit/snapshot.sqlite`)

```sql
-- 1. תמהיל בלוקים בקורפוס הישן (יעד/חימום/סיום/מזווג/ליבה/אחר)
WITH real_sets AS (
  SELECT ws.id, ws.repeats,
    CASE
      WHEN ws.title LIKE 'יעד כפול%' OR ws.title LIKE 'סופר סט%' THEN 'paired'
      WHEN ws.title LIKE 'יעד%' THEN 'target'
      WHEN ws.title LIKE 'חימום%' THEN 'warmup'
      WHEN ws.title LIKE 'סיום%' OR ws.title = 'לסיום' THEN 'finisher'
      WHEN ws.title = 'ליבה' OR ws.title LIKE 'חיזוק ליבה%' OR ws.title LIKE 'חיזוק בטן%' THEN 'core'
      ELSE 'other'
    END AS category
  FROM legacy_workout_sets ws
  JOIN legacy_workouts w ON ws.workoutid = w.id
  WHERE w.targetid IN (13,14,15,16,17,18) AND w.active = 1
)
SELECT category, COUNT(*) AS n, ROUND(100.0*COUNT(*)/(SELECT COUNT(*) FROM real_sets), 1) AS pct
FROM real_sets GROUP BY category ORDER BY n DESC;

-- 2. תמהיל exercise_role בקטלוג החדש, לפי בלוק (main בלבד, ללא זיווג/פרוטוקול)
SELECT
  CASE WHEN domain='core' THEN 'core' ELSE 'target' END AS kind,
  sets, COUNT(*) AS n
FROM workout_exercises
WHERE (exercise_role='main' OR exercise_role IS NULL)
  AND paired_with IS NULL AND protocol_block IS NULL AND pyramid_sequence IS NULL
GROUP BY kind, sets ORDER BY kind, sets;

-- 3. גשר הקטלוגים — כמה מגושרים ובאיזו רמת ביטחון
SELECT match_type, COUNT(*) AS n, ROUND(AVG(confidence), 3) AS avg_confidence
FROM exercise_bridge GROUP BY match_type;

-- 4. בלוקי יעד ממוצעים לאימון לפי משך — ישן
SELECT w.minutes, COUNT(*) AS n_target_blocks, COUNT(DISTINCT w.id) AS n_workouts,
  ROUND(1.0*COUNT(*)/COUNT(DISTINCT w.id), 2) AS avg_per_workout
FROM legacy_workouts w
JOIN legacy_workout_sets ws ON ws.workoutid = w.id
WHERE w.targetid IN (13,14,15,16,17,18) AND w.active = 1
  AND ws.title LIKE 'יעד%' AND ws.title NOT LIKE 'יעד כפול%'
GROUP BY w.minutes ORDER BY w.minutes;

-- 5. בלוקי יעד ממוצעים לאימון לפי משך — חדש
SELECT w.req_duration,
  COUNT(*) AS n_target_exercises, COUNT(DISTINCT we.run_id) AS n_runs,
  ROUND(1.0*COUNT(*)/COUNT(DISTINCT we.run_id), 2) AS avg_per_workout
FROM workout_exercises we
JOIN workouts w ON w.run_id = we.run_id
WHERE (we.exercise_role='main' OR we.exercise_role IS NULL)
  AND we.paired_with IS NULL AND we.protocol_block IS NULL AND we.pyramid_sequence IS NULL
  AND we.domain != 'core'
GROUP BY w.req_duration ORDER BY w.req_duration;

-- 6. רמת מיקום — לתרגיל בודד, ישן מול חדש (עדכן exercise_id/old_id לפי הצורך)
SELECT
  (SELECT ROUND(AVG(w.level),1) FROM legacy_set_exercises se
   JOIN legacy_workout_sets ws ON se.setid=ws.id JOIN legacy_workouts w ON ws.workoutid=w.id
   WHERE se.exerciseid = eb.old_id AND w.targetid IN (13,14,15,16,17,18) AND w.active=1) AS old_avg_level,
  (SELECT ROUND(AVG(user_domain_level),1) FROM workout_exercises WHERE exercise_id = eb.new_id) AS new_avg_level,
  eb.new_name, eb.old_name
FROM exercise_bridge eb
WHERE eb.match_type != 'none' AND eb.new_id = 'REPLACE_WITH_EXERCISE_ID';

-- 7. תרגילים שהמחולל אף פעם לא בוחר (מגושרים, 0 הופעות ב-snapshot)
SELECT eb.new_id, eb.new_name, eb.old_name, eb.match_type
FROM exercise_bridge eb
WHERE eb.match_type != 'none'
  AND NOT EXISTS (SELECT 1 FROM workout_exercises we WHERE we.exercise_id = eb.new_id);

-- 8. כל בלוקי הליבה שאינם בדיוק 2 סבבים (קטגוריה ג, סוג 1)
SELECT name, sets, run_id
FROM workout_exercises
WHERE domain='core' AND (exercise_role='main' OR exercise_role IS NULL)
  AND paired_with IS NULL AND protocol_block IS NULL AND pyramid_sequence IS NULL
  AND sets != 2
ORDER BY sets DESC;

-- 9. פירמידה — אישור ש-100% מהמופעים הם בולט 3
SELECT bolt, COUNT(*) FROM workouts WHERE applied_protocol='pyramid' GROUP BY bolt;

-- 10. טווח חזרות — לתרגיל בודד, ישן מול חדש
SELECT
  (SELECT GROUP_CONCAT(DISTINCT se.min || '-' || se.max) FROM legacy_set_exercises se
   JOIN legacy_workout_sets ws ON se.setid=ws.id JOIN legacy_workouts w ON ws.workoutid=w.id
   WHERE se.exerciseid = eb.old_id AND w.targetid IN (13,14,15,16,17,18) AND w.active=1
     AND se.min IS NOT NULL AND se.max > 0) AS old_ranges,
  (SELECT GROUP_CONCAT(DISTINCT reps) FROM workout_exercises
   WHERE exercise_id = eb.new_id AND is_time_based=0 AND reps IS NOT NULL) AS new_reps,
  eb.new_name
FROM exercise_bridge eb
WHERE eb.match_type != 'none' AND eb.new_id = 'REPLACE_WITH_EXERCISE_ID';

-- 11 (bonus, חלק 5). סטים עובדים ממוצעים לדומיין, ישן מול חדש — §5.1
SELECT 'new' AS side, domain, COUNT(*) AS n, ROUND(AVG(working_sets),2) AS avg_sets
FROM session_volume WHERE domain IN ('push','pull','legs','core') GROUP BY domain
UNION ALL
SELECT 'old' AS side, domain, COUNT(*) AS n, ROUND(AVG(working_sets),2) AS avg_sets
FROM legacy_session_volume WHERE domain IN ('push','pull','legs','core') GROUP BY domain
ORDER BY domain, side;

-- 12 (bonus, חלק 5). סטים עובדים לפי משך, לדומיין נתון — §5.2 (עדכן domain לפי הצורך)
SELECT w.req_duration, ROUND(AVG(sv.working_sets),2) AS new_avg, COUNT(*) AS n
FROM session_volume sv JOIN workouts w ON w.run_id = sv.run_id
WHERE sv.domain = 'push'
GROUP BY w.req_duration ORDER BY w.req_duration;
```
