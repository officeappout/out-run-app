# צל לפי שעה (RC7)

**תאריך:** 21.10.2026 · **המשך של:** `docs/routes/SHADE-LIGHT-DATA.md` §5, `docs/routes/TECHNION-SHADE-IMPORT.md`

## שלב 1: המנוע (`src/lib/shade-hourly/`, טהור, בלי I/O)

| קובץ | מה |
|---|---|
| `sun.ts` | מיקום השמש (אזימוט/גובה) לפי משוואות NOAA, כולל תיקון שבירה. נבדק מול ערכי אלמנך: נקודות השוויון/היפוך 2026, משוואת הזמן, צהריים וזריחה בת"א |
| `israel-time.ts` | שעון ישראל ← UTC בלי תלות ב-tz של המכונה (שעון קיץ: מיום שישי שלפני יום ראשון האחרון של מרץ, עד יום ראשון האחרון של אוקטובר) |
| `time-grid.ts` | הרשת: 12 ימי ייחוס (ה-21 בכל חודש) × 14 שעות (06-19, שעון ישראל). כל תא מייצג שעה שלמה ונדגם באמצע שלה (HH:30). טבלת שמש אחת לעיר |
| `heights.ts` | גובה מבנה: `height` נמדד ← `building:levels` × 3.2 מ' ← ברירת מחדל לפי `building=*` ← 10 מ'. עץ: 7 מ', אטימות חופה 0.85. כל ההנחות קבועים עם שם |
| `obstacles.ts` | אינדקס רשת (50 מ') של "מנסרות": מבנים וחופות עצים (טבעת חיצונית + גובה + אטימות), במערכים טיפוסיים. חצרות פנימיות (holes) לא נתמכות ב-v1 |
| `shadow.ts` | נקודה בצל? קרן אופקית מהנקודה לכיוון השמש באורך `h / tan(גובה)` נכנסת לטביעת הרגל. מדויק למנסרה עם גג שטוח. עוברים רק על תאי הרשת שהקרן חוצה. צל מוגבל ל-300 מ' (שמש נמוכה מאוד). פני שטח מתעלמים מהם ב-v1 |
| `profile.ts` | פרופיל של מקטע: נקודות דגימה כל 10 מ' (אפשר גם הסטה לשתי המדרכות), ממוצע צל ל-168 תאים. תא שהשמש בו מתחת לאופק = `SUN_DOWN` |
| `quantize.ts` | בית אחד לתא: 0-200 = צל 0-1 בצעדים של 0.005, 255 = שמש מתחת לאופק. ממוצע יומי משוקלל-קרינה (משקל `sin(גובה)`) להשוואה ל-SI של הטכניון |
| `city-file.ts` | קובץ עיר בינארי: כותרת + לכל מקטע id, קו (1e-6°) ו-168 בתים. ה-gzip נעשה בסקריפט |

**ביצועים (סינתטי):** עיר בגודל ת"א (45 אלף מבנים, 160 אלף חופות): בניית האינדקס 20ms, כ-3ms לק"מ רחוב (כל 168 התאים). כ-2,500 ק"מ רחוב ← פחות מדקה.

## שלב 2: בניית עיר (`scripts/shade-hourly/build-city.ts`)

```bash
# dry-run (ברירת מחדל): כותב רק ל---out, מדפיס סטטיסטיקה + השוואה ל-SI של הטכניון
TRAILS_OSM_CACHE_DIR=<dir with israel-and-palestine-latest.osm.pbf> \
npx tsx scripts/shade-hourly/build-city.ts --city tel-aviv --out <dir> \
  --file canopy:soi_canopy_otb:<canopy-tlv.geojsonl> \
  --technion <tzel/normalized/tel-aviv.geojson>
# העלאה (דוד בלבד): מוסיפים --apply --project appout-1, ומקלידים YES
```

- **קלט:** OSM מה-PBF המקומי (מבנים עם `height`/`building:levels`, `natural=tree`/`tree_row`, יערות, רחובות הליכה), וקבצים מקומיים דרך `--file kind:sourceId:path` (GeoJSON או GeoJSONSeq, ITM מזוהה ומומר).
- **מקורות** (`src/lib/shade-hourly/sources.ts`): `live` = OSM, חופות מפ"י דרך Open Tree Base (ODbL), Overture (ODbL, לא נשאב ב-v1), Meta CHM (CC BY 4.0, raster, לא נשאב ב-v1). `pending_licence` = מבני ת"א (IView2/513, גובה `gova_simplex_2019`), חופות ת"א 2024 (IView2/574), מבני באר שבע. **`--apply` מסרב כשמקור pending שימש בבנייה.**
- **חופות מפ"י לעיר:** `ogr2ogr -f GeoJSONSeq canopy-tlv.geojsonl canopies.gpkg -spat 34.735 32.025 34.855 32.150` מתוך `processed/canopies/canopies.gpkg` של Open Tree Base (1.23GB, הורדה חד-פעמית; ב-vsicurl זה איטי מדי).
- **פלט:** `<city>.bin.gz` (פורמט `SHH1`, שלב 1) + `<city>.manifest.json` (מקורות, רישיונות, פילוח מקור הגובה, ההשוואה לטכניון). יעד ב-Storage: `shade/hourly/v1/<city>.bin.gz`.
- **מקטעים:** כל way הליכה מפוצל לחתיכות של עד 100 מ'. id = wayId×1000 + חתיכה. מכשולים נקראים עד 300 מ' מחוץ ל-bbox של העיר.

## שלב 3: תשתית תאורה (`src/lib/lighting/`, `scripts/lighting/build-city.ts`)

- **כלל:** נקודה ברחוב מוארת כשיש עמוד תאורה עד **25 מ'** ממנה (`LIT_LAMP_RADIUS_M`, החלטת דוד: 20-30 מ'). חתיכת רחוב (עד 100 מ') מוארת כש-60% מנקודות הדגימה שלה מוארות (`LIT_PIECE_MIN_SHARE`, אותו 0.6 כמו ב-trails). מיזוג עם OSM: `lit=no` גובר, `lit=yes` או פנסים ← מואר, אחרת **לא ידוע** (לא "חשוך").
- **מקורות פנסים** (`src/lib/lighting/registry.ts`): `osm_street_lamps` (live, ODbL). `beer_sheva_street_lights` (data.gov.il, GeoJSON/CSV/SHP, ITM או WGS84) ו-`tel_aviv_lamps` (ArcGIS IView2/997) הם `pending_licence`. עיר חדשה = רשומה ברג'יסטרי + `--lamps key:file` (GeoJSON / GeoJSONSeq / SHP zip) או `--arcgis key --raw dir`. ITM מזוהה ומומר (`dataset-import/itm.ts`).
- **פלט:** `lighting/v1/<city>.json.gz` (JSON עם gzip): רק חתיכות עם תשובה (כן/לא) + סיכום (walkable / known / lit, לפי בסיס). dry-run כברירת מחדל. `--apply --project` + YES, ומסרב כשמקור pending שימש.
- **מסלול:** `measureRouteLighting(line, buildLitIndex(file))` (אותה התאמה כמו `shadeShareForLine`): `litShare` (מתוך האורך הידוע), `litLengthShare` (אורך מואר ÷ כל המסלול; זה האות לדירוג, לא ידוע = לא מתוגמל ולא נענש), `coverage`.
- **מלאי עיר:** כשקיים קובץ תאורה (מ-Storage, read-only, או `--lighting-file=`), שכבת `lighting` מחושבת בשיטה `lamp_proximity_merge`: כיסוי = ידוע ÷ walkable, אורך = מואר, כל המקורות מופיעים, ו-`license_pending` כשמקור pending שימש. בלי קובץ: כמו קודם (כיסוי תגי `lit` ב-OSM).
