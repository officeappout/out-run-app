- **אין עמוד/הצהרת נגישות באפליקציה כלל.** זו לא רק פרצה ב-UX — זו דרישה חוקית עצמאית (תקנות שוויון זכויות לאנשים עם מוגבלות, שירות נגיש, 2013) שחסרה כרגע ב-100% מהמוצר.

- שני באגים **חוצי-מסכים** (מופיעים בכל עמוד שנבדק, כי המקור הוא קומפוננטה גלובלית אחת): קונטיינר ההתראות (`PushForegroundToast`) ונושא הניגודיות של ה-CTA הראשי.

### 2.1 [CRITICAL] 3 כפתורי מפה בלי שם נגיש (`button-name`, axe)

מסך `/map` בלבד — אבל זו ליבת המוצר, לא עמוד שוליים.

שימו לב: כפתורים סמוכים באותו קובץ (`DiscoverLayer.tsx:95,102` — "דיווח מהיר", "הוסף מיקום") **כן** עברו, כי יש להם `title` — ההבדל היחיד בין עובר/נכשל הוא ההוספה של attribute אחד.

⚠️ **הערה חשובה לפני מימוש בפועל (לא לשלב 1):** `DiscoverLayer.tsx` ו-`MapShell`/`AppMap` הם קבצים ש[[map-nav-ownership-boundary]] מסמן כבבעלות דוד — לעצור ולשאול לפני עריכה, גם אם השינוי טריוויאלי כמו הוספת `aria-label`.

### 2.2 [SERIOUS] ARIA אסורה על קונטיינר ההתראות — כל מסך (`aria-prohibited-attr`, axe+Lighthouse)

`src/components/system/PushForegroundToast.tsx:118-121` — `<div>` (role מרומז `generic`) עם `aria-live="polite"` + `aria-label="התראות פוש בזמן אמת"`. לפי מפרט ARIA-in-HTML, `aria-label` אסור על role `generic`. מרונדר ב-`ClientLayout` → מופיע **בכל עמוד** באפליקציה.

**תיקון מוצע:** להוסיף `role="region"` לאלמנט (role שמתיר `aria-label` + `aria-live`) — שינוי שורה אחת, קומפוננטה גלובלית אחת, משפיע על כל המוצר.

### 2.3 [SERIOUS] ניגודיות צבעים — 3 דוגמאות קונקרטיות שנמדדו בפועל

| מיקום | צבעים | יחס ניגודיות נמדד | דרוש AA |
|---|---|---|---|
| כפתור CTA ראשי "הרשמה מהירה" (עמוד הבית) | טקסט לבן על `#5BC2F2` | **2.01:1** | 4.5:1 (טקסט רגיל, 16px bold אינו "טקסט גדול") |
| כפתור "שלחו בקשת מחיקה" (`/delete-data`) | טקסט לבן על `bg-rose-500` (`#f43f5e`) | **3.67:1** | 4.5:1 (14px bold) |
| טקסט `text-slate-400` — **131 קבצים** בסקופ הצרכני משתמשים בצבע הזה | `#94a3b8` על רקע לבן | **2.56:1** | 4.5:1 |

השורה השלישית היא לא באג נקודתי — זו בעיית **token עיצובי חסר** (כבר מתועד ב-[[color-system-map]]: אין SoT לצבעים ברמת האפליקציה). תיקון אמיתי = להחליף את ה-token ברמת העיצוב (למשל `slate-500`/`#64748b` ומעלה), לא לתקן קובץ-קובץ.

### 2.4 [MODERATE] `<main>` כפול/מקונן — 3 מסכים (`landmark-no-duplicate-main`, `landmark-main-is-top-level`, axe)

ה-shell הגלובלי (`src/app/ClientLayout.tsx:110`) כבר עוטף **כל** עמוד ב-`<main>` אחד. שלושה עמודים מרנדרים `<main>` פנימי משלהם, ויוצרים landmark כפול/מקונן:

- `src/app/privacy/page.tsx`
- `src/app/delete-data/page.tsx`
- `src/app/map/MapShell.tsx` (⚠️ קובץ בבעלות דוד — ראו §2.1)

**תיקון מוצע:** בכל אחד מהשלושה, להחליף את ה-`<main>` הפנימי ל-`<div>` (או `<article>` אם מתאים סמנטית) — ה-shell הגלובלי כבר מספק את ה-landmark היחיד שצריך.

### 2.5 [MODERATE] כותרת עמוד גנרית / חסר H1

`/` ו-`/gateway` מציגים `<title>Out Run App</title>` — לא ספציפי לעמוד (WCAG 2.4.2). `/gateway` גם חסר כל `<h1>` בעמוד (`page-has-heading-one`, Lighthouse).

## 6. מסכים הדורשים Login — שיטת ביצוע (בוצע 12.10.2026, ראו §9 לממצאים)

**השיטה הנכונה — לא דורשת סיסמה, לא דורשת שאני אמציא schema, לא דורשת שתשלח לי שום secret:**

1. אתה (או אני, אם תעדיף) פותח דפדפן/incognito חדש, נכנס ל-`outrun.co.il`, ועושה הרשמה אחת עם חשבון Google/Apple חד-פעמי שאינו שייך למשתמש אמיתי (Gmail זניח שבשליטתך), ועובר את ה-onboarding **הרגיל** עד `/home`. זה בונה פרופיל Firestore תקין ב-100%, כי זה עובר בדיוק באותו קוד שמשתמש אמיתי עובר — אין שום ניחוש schema.
2. מוצאים את ה-UID של החשבון הזה (מסוף Firebase → Authentication, או ב-Firestore תחת `users/` — המסמך האחרון).
3. מריץ מקומית (איפה שה-`.env.local`/service-account key האמיתיים נמצאים — **לא בתוך ה-worktree המבודד שלי, שם אין לי אותם בכלל**):

```ts
// scripts/_mint-a11y-test-token.ts — קובץ חד-פעמי, למחוק אחרי שימוש, לא ל-commit
import { getAdminAuth } from '../src/lib/firebase-admin';

const uid = process.argv[2];
if (!uid) { console.error('Usage: npx tsx scripts/_mint-a11y-test-token.ts <uid>'); process.exit(1); }

getAdminAuth().createCustomToken(uid).then((token) => {
  console.log(token);
});
```

הרצה: `npx tsx scripts/_mint-a11y-test-token.ts <UID>`

4. שולח לי את ה-token המודפס. זה **בטוח לשלוח** — טוקן חתום לטווח-קצר (שעה), תקף רק ל-UID הבודד הזה, לא סיסמה ולא service-account key. אני אשתמש בו דרך Firebase JS SDK (ה-config הציבורי כבר ב-`src/lib/firebase.ts`) כדי להתחבר בדפדפן Playwright ולהריץ axe+Lighthouse על `/home`, `/map`, `/run`, `/active-workout-ui`, `/profile` — בדיוק כמו שעשיתי על המסכים הציבוריים.
5. בסיום ה-audit, החשבון נשאר חשבון-בדיקה תקין בפרודקשן (לא דורש מחיקה), אבל כדאי למחוק את `scripts/_mint-a11y-test-token.ts` אחרי השימוש — לא להשאיר סקריפט חד-פעמי בריפו ([[seed-scripts-must-not-outlive-their-bootstrap]]).

**הצעד הבא בפועל:** בחירת כלי קונקרטי (Nagich/EqualWeb/UserWay/אחר) — לא הוחלט כאן, דורש השוואת מחיר/זמן-אינטגרציה שלא בוצעה בשלב 1 הזה.
